# The linker and symbol resolution

## The pipeline

`AstLinker::link` (`src/AstLinker.cpp`) runs an ordered list of passes over the
parsed `GlobalScope`s. `linkPasses` is the list; read it before adding
anything. In order:

| Pass | Class | Does |
|---|---|---|
| building the symbol tree | `TaskBuildSymbolTree` | root scope, one `SymbolScope` per named scope; takes ownership of the units |
| resolving imports | `TaskResolveImports` | every import's target, from where it is written |
| applying type extensions | `TaskApplyTypeExtensions` | merges `extend` members into the type; records instance extensions |
| checking imports | `TaskCheckImports` | where an import may be written (18.1.3) |
| resolving super types | `TaskResolveSuperTypes` | base types, before any member reference |
| resolving override actions | `TaskResolveOverrideActions` | `override` actions via the component's base chain |
| checking for inheritance cycles | `TaskCheckTypeCycles` | reports and marks cycles so walkers stop |
| resolving references | `TaskResolveRefs` | every remaining reference |
| resolving instance extensions | `TaskResolveRefs::resolveInstanceExtensions` | `extend struct S<2>` bodies |
| binding compile-time conditions | `TaskResolveRefs::resolveCompileConds` | `compile if` conditions, for tools |
| post-resolve actions | `ResolveContext::runPostResolveActions` | deferred work (sizing `sizeof_s<T>`) |
| packed-struct checks | `TaskCheckPackedStructs`, `TaskCheckPackedUses` | 21.13.1 |
| completeness gate | `TaskCheckRefsResolved` | any reference still unbound is reported |

Ordering matters. A pass that needs super types must run after
`TaskResolveSuperTypes`; the completeness gate is last on purpose.

**No exception escapes `link`.** Each pass runs under a catch-all that turns
an exception into one PSS000 marker naming the current pass (the `pass`
string). Set `pass` for any new pass, so an internal error says where it came
from.

## The main classes

- **`ResolveContext`** (`src/ResolveContext.h`): shared state for one link:
  factory, marker listener, root, the symbol-table iterator (scope stack),
  extension declaring-scopes, instance extensions, post-resolve actions.
  Passes take a `ResolveContext *`.
- **`NameLookup`** (`src/NameLookup.h`): *the* implementation of LRM 18.3
  (plus 17.2 extensions, 18.1.3 imports, 10.3 template parameters). Every
  resolver asks it what a name means; none searches a symbol table itself.
  Its header comment is the specification of the lookup order: read it before
  changing any lookup behaviour.
- **`TaskResolveRefs`**: the walker. A `VisitorBase` subclass that visits
  every statement, expression and scope, and resolves the references it finds.
  Constructs such as `foreach`, `randomize ... with`, activities and
  constraints push scopes here.
- **`TaskResolveRef`**: resolves *one* reference (a `TypeIdentifier` or an
  `ExprRefPath*`) to an `ISymbolRefPath`. Handles template arguments and
  specialization via `TaskSpecializeParameterizedRef` /
  `TaskGetSpecializedTemplateType`.
- **`CoreLibraryLookup`**: when a name fails, maps it to the core-library
  package that declares it, so the message can say `add 'import std_pkg::*;'`.

A reference is bound by setting its *target* (an `ISymbolRefPath`: a path of
child indices from the root). Consumers, including `pssparser.refs`, follow
those paths.

## Rules

### Use NodeKind, never `dynamic_cast`, on AST nodes

The AST interfaces inherit `public virtual`, so `dynamic_cast` walks the base
graph and compares type names with `strcmp`. It once made up almost all of link
time. `NodeKind` (`src/include/pssp/impl/NodeKind.h`, generated by
`scripts/gen_node_kind.py`) classifies a node with one virtual dispatch:

```cpp
ast::IFoo *f = NodeKind::cast<ast::IFoo>(node);   // one question

NodeKind nk(node);                                // several on one node
if (ast::IFoo *f = nk.as<ast::IFoo>()) { ... }
else if (nk.is<ast::IBar>()) { ... }
```

`tests/python/test_no_ast_dynamic_cast.py` fails on a `dynamic_cast` to an AST
type in `src/`. Build with `PSSP_NODEKIND_CHECK` defined to cross-check every
NodeKind answer against `dynamic_cast` when debugging.

### Overrides must visit every child

An override of a generated `visitX` in `TaskResolveRefs` that does not chain to
`VisitorBase::visitX` must visit each child field itself. Forgetting one is
how defaults, repeat counts, slice bounds and initializers went unresolved.
`tests/python/test_resolver_override_coverage.py` checks direct children; a
deliberate skip goes in its `ALLOWED` list with a reason.

### Never fail silently

A resolution path that fails must report. The completeness gate
(`TaskCheckRefsResolved`) catches an unbound reference nobody reported, but it
cannot say *why*; report at the failure site with a specific message. Every new
message needs a marker ID (see `error-suites.md`).

### Index paths are fragile

Targets are child-index paths. Anything that changes a scope's children
(injecting a node, merging extensions, copying for a specialization) shifts
indices. Symptoms: a reference resolves to the wrong member, or falls off the
end of the child list and is silently never checked. An inherited member must
be addressed by a path through the type that declares it, not the derived one.
Compiler-injected nodes (`lineno == -1`) are a classic mask for this; see
`ast-regen.md`.

### Templates

- A generic's body is copied per specialization (`TaskCopyAst`) and its
  references re-resolve in each copy. `TaskCopyAst::setPreserveExprTargets()` is
  default-off and must stay so; it is enabled only for the bound value-argument
  copy (`TaskBuildParamValList`). Preserving targets wholesale freezes, for
  example, an array dimension `a[N]` to one value across all specializations.
- Template *arguments* resolve at the use site. `T a[N]` is rewritten into the
  builtin generic `array<T, SZ>`, and its dimension is an expression argument.
- Never resolve a template argument by delegating to
  `TaskResolveRefs::visitExprRefPathStatic`: it probes the whole type scope and
  re-enters the field being resolved (unbounded recursion). Use the lookup-only
  `TaskResolveRef::resolveStaticArgPath`.
- When testing value arguments, vary the element type too: specializations
  whose parameter lists compare equal share one instance and can hide a broken
  argument.
- `setTarget` owns what it is given; never pass it the pointer the node
  already holds.

### Extensions

`extend` members are moved into the extended type before reference resolution.
`ResolveContext` records the scope that lexically declares each extension, so a
member an `extend` contributed resolves with its declaring package's names in
scope (17.2). Instance extensions (`extend struct S<2>`) apply when a matching
specialization is made.

## Gates that measure the linker

Run these after any linker change. Each compares against a baseline in
`tests/python/baselines/` and fails on drift in *either* direction; an
improvement is recorded by regenerating the baseline in the same change.

```bash
PYTHONPATH=python python scripts/refcov.py check      # references bound / reported
PYTHONPATH=python python scripts/refcov.py baseline
PYTHONPATH=python python scripts/occgate.py check     # pssparser.refs occurrences
PYTHONPATH=python python scripts/occgate.py baseline
```

`scripts/refcov.py` reports, over the legal corpus, every reference field and
whether it was bound, left unbound (a silent failure), or dead;
`scripts/refcov_slots.py` substitutes an undefined name into each slot and checks
it is reported on the right line. `scripts/occgate.py` checks that
`pssparser.refs.occurrences()` covers every identifier token.

## Performance

Compare instruction counts (callgrind), not wall time. A rebuild alone can
move counts by a fraction of a percent through code and string layout; for a
small change, confirm the delta with an A/B build (back the change out,
rebuild, measure) before believing it.
