Lint Rule Function Reference
============================

Every operator, function and macro a declarative lint rule's expressions can
use, generated from the lint engine's function registry by
``scripts/gen_lint_functions.py`` -- do not edit this file by hand, it will be
overwritten.

Rule expressions are written in a subset of `CEL
<https://github.com/google/cel-spec>`_, the Common Expression Language. The
standard functions below behave as the CEL specification defines them, and as
cel-go does where the specification leaves a detail open. The groups from
*Kind tests* on are the PSS library, which CEL does not have: pss-rules adds
them. Types are written as in CEL: ``list(A)`` is a list whose elements have
type ``A``, ``A`` and ``B`` are type parameters, and ``node`` is any PSS
syntax-tree node.

Each entry gives:

* **Level** -- what analysis the function needs: ``L0`` syntax only, ``L1``
  symbol resolution, ``L2`` types, ``L3`` constant values, ``L4`` the whole
  model. A rule's level is the highest level of the functions it calls.
* **Scope** -- ``file`` or ``model``. A rule that calls a ``model`` function
  is re-run on any change to the model; others only when their file changes.
* **Cost** -- what a call adds to the rule's evaluation budget, beyond one
  step per expression evaluated: ``constant``; ``linear``, one step per list
  or map element and per 64 string bytes in the operands; or ``custom``, as
  the description says.

``[]``
~~~~~~

**Level:** L0; **Scope:** file

.. list-table::
   :header-rows: 1

   * - Signature

     - Overload
   * - ``list(A)[int] -> A``
     - constant

``list(A)[int] -> A``
   The element at a zero-based index. Out of range is an error; use ``l[?i]`` when the index may be out of range.

``map(K, V)[K] -> V``
   The value under a key. A missing key is an error; use ``m[?k]`` or ``m.?k`` when the key may be absent.

   Indexing an optional list applies to its value and stays optional: ``optional.of(l)[i]`` is ``l[?i]``, and ``optional.none()[i]`` is ``optional.none()``.

``optional(map(K, V))[K] -> optional(V)``
   Indexing an optional map applies to its value and stays optional: ``optional.of(m)[k]`` is ``m[?k]``.

.. _lint-fn-matches:

``matches``
~~~~~~~~~~~

**Level:** L0; **Scope:** file

.. list-table::
   :header-rows: 1

   * - Signature

   * - ``matches(string, string) -> bool``

.. _lint-fn-node-isa:

``isa``
~~~~~~~

**Level:** L0; **Scope:** file

.. list-table::
   :header-rows: 1

   * - Signature
     - Cost
     - Overload
   * - ``node.isa(type) -> bool``
     - constant
     - ``node_isa``

Whether the node is of the class named, or of a class deriving from it: ``node.isa(ConstraintStmt)``. The argument must be a node class. Unlike ``type(n) == K``, which tests the exact class, ``isa`` follows the ``super:`` chains of the AST schema. Like ``type(n) == K``, it narrows: on the right of ``&&``, and in the first result of ``?:``, ``n`` has class ``K``.

.. _lint-fn-enclosing-node-type:

``enclosing``
~~~~~~~~~~~~~

**Level:** L0; **Scope:** file

.. list-table::
   :header-rows: 1

   * - Signature
     - Cost
     - Overload
   * - ``enclosing(node, type) -> node``
     - custom
     - ``enclosing_node_type``

The nearest owner of the class named, or of a class deriving from it: ``enclosing(node, Action)``. The result has that class, so its fields can be read directly (``enclosing(node, Action).name``). ``null`` when there is none; reading a field through ``null`` is an error, so test ``enclosing(node, K) != null`` first where there may be none. The node itself is not considered. One step per owner visited.

The other elements of the list that holds the node (the statements of its block, the items of its scope), in order and without the node itself. Empty when the node is not a list element (``ExprBin.lhs``) or is a root. One step per element.
